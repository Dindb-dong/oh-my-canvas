# Oh My Canvas への貢献

[English](../../CONTRIBUTING.md) · [한국어](ko.md) · **日本語** · [简体中文](zh-CN.md)

再現可能な不具合報告、翻訳の改善、コンポーネントの修正、範囲が明確なコード変更を歓迎します。

> **ライセンスと出自を確認してください。** 独立して記述したプロジェクトコードには [MITライセンス](../../LICENSE) が適用され、外部資料には各自の条件が適用されます。ライセンスを付与できる資料だけを提出し、[第三者の通知](../../THIRD_PARTY_NOTICES.md)を保持してください。除去した会社コードやコピーしたテストを再導入しないでください。新たなCLAや権利譲渡は導入しません。

## 貢献の種類

| 種類 | 添えるもの |
| --- | --- |
| 不具合修正 | 最小の合成データ、期待と実際の結果、回帰テスト |
| UI改善 | 実際の変更前後の画面、キーボード・フォーカス、関連する画面幅の確認 |
| コンポーネント・variant | メインとインスタンス、override、Undo、保存・再読込の確認 |
| 文書・翻訳 | 正常なリンク、正しいコマンド、各言語で一致する数値と制限 |
| 大きな機能 | 実装前に具体的な問題、利用例、範囲、代替案と負担 |

現在はローカルで管理しており、公開リモートは設定されていません。Issue・PRテンプレートは将来のホスティングに備えたものです。それまでは同じ形式のローカル報告書やレビュー用メモを使ってください。公開Issue、リリース、自動CIの存在を前提にしないでください。

## ローカル環境

利用許可のあるチェックアウト、Node.js **22.12以上**、npmを用意し、リポジトリのルートで実行します。

```sh
npm ci
npm run build
npm start
```

開発には `npm run dev` を使えます。新しいローカル受け入れ検査はmacOS arm64で実行し、合格した検査と残作業は [現在の検証記録](../independent/VERIFICATION.md) に分けています。Windows/Linuxでの実行は未検証です。パッケージ版MCP CLIに別途Nodeは不要です。

重要な文書の唯一のコピーをテストに使わず、合成データと独立したプロファイルを使用してください。保存・形式変更の検証前に `.omc` をバックアップします。[開始ガイド](../GETTING_STARTED.md)と[構成](../ARCHITECTURE.md)も参照できます。

## 変更とレビューの流れ

1. 合意した基準コミットから `fix/text-undo`、`feat/component-property`、`docs/japanese-readme` などのブランチを作成し、無関係な作業を保持します。
2. まず問題を再現して呼出経路を追い、既存の編集・保存・UIパターンを再利用します。
3. 一度にレビューできる範囲に絞り、重要な動作には回帰テストを追加します。利用者向けの動作や互換性が変わる場合は文書も更新します。
4. 影響する検査を実行し、未実行の検査を成功と記載しないでください。
5. diffから個人文書、秘密、生成物、無関係な編集を除きます。コミットの件名は `fix: preserve text session undo` のように明確な英語で記述します。
6. [PRテンプレート](../../.github/PULL_REQUEST_TEMPLATE.md)でPRまたはローカルレビュー用メモを用意します。管理者の承認なしにマージ・公開・デプロイしないでください。

## 必要な検査

通常の検査はローカルで実行でき、Dockerの準備は不要です。

```sh
npm run check
npm test
npm run test:editor
```

アプリ連携を変更したら先にビルドし、影響する実機Electron検査を選択します。

```sh
npm run build
npm run test:e2e
node scripts/independent-host-e2e.mjs
node scripts/independent-ui-e2e.mjs
node scripts/independent-render-e2e.mjs
node scripts/independent-library-e2e.mjs
```

それぞれ独立した受入検査です。実際に実行したコマンドと結果を記録してください。一時プロファイルで実際のアプリを起動し、一部は `docs/qa/` の画面や結果を更新します。生成物を確認せずにコミットしないでください。サンドボックスではloopback/TLSやElectron起動にホストの通常の実行許可が必要な場合があります。

パッケージ変更時は先にビルドし、ローカルのステージングツールを使います。ロックされた実行時依存を作業専用ディレクトリへ実体ファイルとしてコピーし、インストール済みElectronを再利用します。別worktreeへの `node_modules` リンクから直接梱包すると依存が欠落する場合があります。

```sh
npm run build
node scripts/package-local.mjs
node scripts/packaged-smoke.mjs
```

これらはローカル生成と検査のみで、公開やインストール済みアプリの置き換えは行いません。無関係な検査で既存アプリやグローバルMCP設定を変更しないでください。旧 `--installed`・既定プロファイル用スクリプトは現在の独立エンジン受け入れ手順ではありません。別途許可・確認されたインストール検査だけで使ってください。

文書のみの変更では `node scripts/check-docs.mjs` を実行し、描画された画像と翻訳を確認してください。通常、アプリ全体の再ビルドは不要です。[検査ガイド](../TESTING.md)、[トラブルシューティング](../TROUBLESHOOTING.md)、[検証記録](../independent/VERIFICATION.md)も参照してください。過去のテスト件数はその時点の記録です。

## 保持すべき動作

- 保存では原子的書込、バックアップ復旧、実状態を変更する前の検証、容量制限を保持します。
- 共同編集では収束、参加者別Undo、一貫した座標、人数制限を保持します。同一Macでの4クライアントTLS検査は外部インターネット/NAT到達性の証明ではありません。
- MCPはloopbackと認証・Origin/Host検査を保持します。**MCPをポート転送しないでください。** ユーザーのテキスト編集・値のスクラブ中は読取可能で、変更は完了まで `busy` を返します。
- 保存・通信はv2で、v1文書は引き続き読めます。互換性を検査し、非互換のピアは明示的に拒否してください。
- テレメトリ、リモート素材、アカウント、有料サービスへの依存は明示的な製品判断なしに追加しないでください。

## 不具合と機能の提案

[不具合フォーム](../../.github/ISSUE_TEMPLATE/bug_report.yml)にアプリ・ソースのコミット、OS・アーキテクチャ、正確な手順、期待と実際の動作を書いてください。関連する場合は保存・再読込、Undo、ホスト・参加者数と接続状態も含めます。

添付は最小の合成文書と秘匿情報を除いた画面・ログに限定します。顧客デザイン、個人情報、認証情報、セッション招待、トークン、`mcp-runtime.json`、ユーザーデータフォルダ全体を添付しないでください。招待は編集権を与え、`.omc` は素材とマージ履歴を含みます。見えるレイヤーを削除しても過去の内容が消えるとは限りません。新しい合成文書で再現してください。

セキュリティの懸念は[セキュリティ方針](../../SECURITY.md)を参照し、管理者と既に合意した非公開の連絡手段を使用してください。秘密や機密文書、他者のシステムへの攻撃を公開Issueに記載しないでください。専用メールや応答期限があると仮定しないでください。

[機能フォーム](../../.github/ISSUE_TEMPLATE/feature_request.yml)には、問題、最小の解決動作、代替案、保存・共同編集・MCP・権限・ネットワークへの影響を記載します。レビュー前に実装や公開日を約束しないでください。

## 翻訳とレビュー

コマンドと共通の技術情報は英語READMEと[英語の貢献ガイド](../../CONTRIBUTING.md)を基準にします。前提条件、数値、形式、制限、検証済み環境を変える際は関係する四言語を揃えてください。実際の英語UIラベル、ツール名、API、コマンドはそのままにして説明を翻訳します。

オフラインのチェックアウトでも使える相対リンクとリポジトリ内の画像、説明的な代替テキストを使います。実際の画面を示し、存在しない機能や私的文書を載せないでください。レビューでは人ではなく動作・根拠・コードを具体的かつ敬意を持って議論します。
