# W6 five-document shared-resource endurance plan

Generate the offline plan from the measurement checkout with Node. Save it under the primary checkout's private `internal/docs/` artifact tree. This command writes JSON to stdout and does not start an application.

```sh
node tools/local-dev-bench/omc-native/w6.mjs --seed 101
node --test tools/local-dev-bench/omc-native/w6.test.mjs
```

Each seed expands one 60-minute active run. Every minute switches all five retained document leases, traverses ten distinct pages, performs twenty primitive edits in ten owner groups, exercises each group's Undo and Redo, reads ten bounded PNGs, and opens and closes one temporary document. Every fifth minute adds two ordinary job admissions. The four quiescent intervals take place outside the 60 active minutes and follow job drain, GPU fences and 30 seconds of idle. Seeds 101, 202 and 303 require independent processes and isolated profiles. The import input is registered here as D-REAL.

## Installed service and desktop routes

| Operation | Route and required evidence |
| --- | --- |
| Retained leases and hidden editor navigation | Give each document an actual session and retain its lease using `workspace.open` or the bounded legacy `open_document` route. Check five distinct durable authorities. Use `workspace focus` and `select_page` for hidden navigation, check the resulting document/page identities, and require that the isolated window remains unfocused. |
| Grouped edits and undo/redo | Submit two `node.set` commands as one typed batch with explicit document, owner, idempotency key and current revision. Use `document.undo` and `document.redo` on the same session. An independent read must confirm the expected two properties and the remainder of the authored state after each transition. |
| Bounded screenshot | Use `document.export` PNG with an explicit page and 320 × 200 viewport. Validate native revision, dimensions, PNG integrity, and independently registered pixels where expected. Select visible source regions that exercise the shared assets when binding targets. Software PNG is raster evidence. |
| Temporary, import and export | Hold one reusable temporary document with an independent lease and release it with `workspace.close` after each open. Submit import and full portable OMC export through `native_job`, retain job statuses, check durable staged import and export integrity, then release completed result/snapshot leases as appropriate. |
| Abandoned leases | Separately keep the owning session alive without touching its query cursor for at least 60 seconds or result handle for at least 300 seconds. Check initial usability and record server expiry. Do not treat an error from a different owner as expiry evidence. |
| Checkpoint | `workspace.metrics` supplies active and queued job counters and transport reservations. Stop new offers and drain confirmed work before starting GPU fence and idle evidence. Record active schedule slip, drain time and idle time separately. |

Bind the plan's document, page and editable target slots to manifest identities, freeze complete request bodies and expected outcomes, and record every offered operation, timeout, rejection and terminal result. Keep queue overruns explicit. Retain no output bytes from successful large jobs beyond the verified artifacts needed for audit. Run only in a task-owned profile, with the drawing window hidden under `--automation-background`. Use a prelaunch through shutdown full-process resource collector with at most 50 ms sampling and observed fork/exit tracking. Follow the qualification guide for the registered machine, warmup, managed memory and RSS ceilings, retained-allocation trend, and evidence schema.

## Readiness at the pinned installed release

- D-RES-S needs a candidate-native D-NATIVE conversion and four fully manifested D-100K documents with independently identified authorities and verified shared immutable asset/font hashes. The simple native scale fixtures have scalar rectangles and cannot substitute for D-100K paths, text, images, layout, masks and effects. The installed D-REAL ordinary native job route has a 64 MiB file-read cap. D-REAL contains 160,627,671 bytes. Continued dependent W6 runtime requires a service that admits this input and a candidate-native D-NATIVE conversion.
- The pinned desktop client defaults to a 16 MiB regular response cap for `Request::Open` via `workspace.open`. Higher-load navigation requires a proven bounded desktop open path. The headless service and lightweight fixture are valid for operation-level qualification.
- Installed `workspace.metrics` has job counts, session counts, worker PIDs and transport reservations. It has no coherent managed CPU/GPU allocation breakdown or GPU fence evidence. Synchronous software PNG completion, empty job counters and process RSS do not establish GPU completion or the managed retention gate. Instrument the actual backend and combine it with independently sampled process memory.
- W6 qualification remains incomplete. This artifact supplies operation counts and bindings to resolve; it contains no installed runtime outcomes or resource sample.
